# 教訓（同じ指摘を繰り返さないための蓄積）

各ランの冒頭で読み、計画と指示に反映する。追加前に既存項目と重複・矛盾しないか確認し、あれば統合する。

## 形式
```
### <ルールを一文で>
- 出所: user | verifier | reviewer | self（日付）
- 範囲: 全体 | <エージェント名>
- Why: なぜ必要か（起きた問題）
- How: どう適用するか
```

## 項目

### 進め方は対話を基本にし、重要な分岐では先に確認する
- 出所: user（2026-10-04）
- 範囲: 全体
- Why: 自律で走り切る進め方は望まれていない。
- How: SKILL.md の対話ゲート（開始・編成承認・フェーズ区切り・分岐点）で確認する。

### 指摘は利用者のものもエージェントのものも lessons.md に取り込む
- 出所: user（2026-10-04）
- 範囲: 全体
- Why: 同じ指摘を何度もさせないため。
- How: SKILL.md の改善ループに従う。

### ハーネスを更新したら dotfiles も同時に更新し、ローカルコミットする（push はしない）
- 出所: user（2026-10-04）
- 範囲: 全体
- Why: どの環境でも再現できる状態を保つため。
- How: SKILL.md の改善ループの手順 6・7 に従う。ハーネス関連パスだけをコミットする。
