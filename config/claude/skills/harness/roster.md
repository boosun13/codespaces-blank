# 手札（モデル名鑑）

| 手札 | 得意 | 避ける | コスト |
|---|---|---|---|
| claude opus (`opus`) | 計画・設計・曖昧な要件の解釈・最終レビュー・統合 | 大量の単純作業 | 高 |
| claude sonnet (`sonnet`) | 実装・テスト実行・ファイル操作を伴う作業、橋渡し役 | 深い設計判断 | 中 |
| codex astra (`gpt-6-astra`) | 最難関のバグ・アルゴリズム・独立した第二意見レビュー | 簡単な作業 | 最高 |
| codex sol (`gpt-6.1-sol`) | コーディングの主力。実装・リファクタ・テスト生成 | — | 中 |
| codex terra (`gpt-5.6-terra`) | 標準的で素直な実装 | 難問 | 低〜中 |
| codex luna (`gpt-6-luna`) | 高速・安価。整形、grep的調査、定型変換、下書き | 推論の深い作業 | 低 |
| agy gemini pro (`gemini-3.1-pro`) | 長大コンテキストの読解・資料横断調査・要約・別系統の視点 | 精密な編集 | 中 |
| agy gemini flash (`gemini-3.8-flash`) | 大量の軽い調査・分類・要約を安く速く | 難問 | 低 |

原則: 難度に見合う最小のモデルを選ぶ。重要な成果物は「作る人」と「レビューする人」を別系統のモデルにする。
